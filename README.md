# EchoForge — Audio Transcription & Context Risk Analyzer

## Overview

EchoForge is a Python-based audio analysis module that processes an audio recording through three main stages:

1. **Audio conversion** — converts supported audio files to mono, 16 kHz WAV using FFmpeg.
2. **Speech-to-text transcription** — uses OpenAI Whisper (`tiny` model) to convert the audio into text and timestamped speech segments.
3. **Context/risk analysis** — scans the transcript for suspicious keywords and phrases related to credentials, finance, urgency, authority references, and suspicious actions, then assigns a risk score and risk level.

The module also saves the complete analysis as a JSON file for use by other components of the larger project.

---

## Features

- Converts audio to Whisper-friendly WAV format.
- Supports common input audio formats handled by FFmpeg, including `.m4a` and `.wav`.
- Speech-to-text transcription using the Whisper `tiny` model.
- Produces timestamped transcript segments.
- Keyword-based suspicious-context detection.
- Calculates a context risk score from **0–100**.
- Classifies the result as **LOW**, **MEDIUM**, or **HIGH** risk.
- Generates human-readable reasons explaining why content was flagged.
- Saves the complete processing result to `output/result.json`.
- Uses an external `keywords.json` file so detection terms can be modified without changing the analyzer code.

## Usage

### Run the Complete Pipeline

From the project directory:

```bash
python main.py
```

The current `main.py` uses:

```python
audio_path = "audio/sample 1.m4a"
```

To process a different audio file, change this path to the desired input file.

For example:

```python
audio_path = "audio/Test Rec 2.m4a"
```

### What Happens When `main.py` Runs

#### 1. Audio Conversion

The input audio is converted using FFmpeg with:

- Sample rate: **16,000 Hz**
- Channels: **1 (mono)**
- Output format: **WAV**

The converted file is written to the `audio/` directory.

#### 2. Speech Recognition

Whisper's `tiny` model transcribes the converted WAV file.

The module produces:

- A complete transcript
- Individual speech segments
- Start and end timestamps for each segment

Example:

```json
{
    "start": 0.0,
    "end": 3.0,
    "text": "Hey, are we still meeting at 5?"
}
```

#### 3. Context Analysis

The transcript is converted to lowercase and checked against the keyword lists in `keywords.json`.

Detected categories are collected and assigned a risk score.

#### 4. Result Display

The program prints:

- Transcript
- Timestamped segments
- Context score
- Risk level
- Reasons for flagging

#### 5. JSON Output

The complete result is saved to:

```text
output/result.json
```

## Risk Scoring

The context analyzer uses the following scores:

| Category | Score |
|---|---:|
| Credential request | +30 |
| Financial content | +20 |
| Urgency language | +15 |
| Authority/official identity reference | +15 |
| Suspicious action | +20 |

The final score is capped at **100**.

### Risk Levels

| Score | Risk Level |
|---:|---|
| 0–29 | LOW |
| 30–59 | MEDIUM |
| 60–100 | HIGH |

For example, if a transcript contains both credential-related content and financial content:

```text
Credential request = 30
Financial = 20
----------------
Total = 50
Risk = MEDIUM
```

## Output Format

`output/result.json` contains the following information:

```json
{
    "original_audio": "audio/sample 1.m4a",
    "converted_audio": "audio/sample 1_conv.wav",
    "transcript": "...",
    "segments": [
        {
            "start": 0.0,
            "end": 3.0,
            "text": "..."
        }
    ],
    "context_score": 0,
    "risk_level": "LOW",
    "detected": {},
    "reasons": []
}
```

### Output Fields

| Field | Description |
|---|---|
| `original_audio` | Path of the original input audio |
| `converted_audio` | Path of the generated WAV file |
| `transcript` | Complete speech-to-text result |
| `segments` | Timestamped transcription segments |
| `context_score` | Calculated risk score from 0–100 |
| `risk_level` | `LOW`, `MEDIUM`, or `HIGH` |
| `detected` | Categories and matching keywords found |
| `reasons` | Human-readable explanations for detected risk indicators |

## Important Implementation Notes

- The Whisper model is currently hard-coded to `tiny` in `transcribe.py`.
- The Whisper model is loaded when `transcribe.py` is imported.
- Keyword matching is currently based on simple substring matching rather than semantic/NLP classification.
- A category contributes its configured score once when at least one matching keyword is detected; multiple matches within the same category do not add the category's score repeatedly.
- Scores for categories not present in the `SCORES` dictionary default to `0`.
- Human-readable explanations are generated only for categories present in the `REASONS` dictionary.
- `main.py` currently uses relative paths, so it should be executed from the module's project directory.
- `audio_converter.py` overwrites an existing converted file because FFmpeg is invoked with the `-y` option.

---

## Limitations

The current implementation is a rule-based prototype and has several limitations:

1. **Keyword matching can produce false positives.** A word such as `bank` may be detected even when the surrounding context is harmless.
2. **Semantic context is not analyzed.** The analyzer checks whether configured strings occur in the transcript rather than understanding the meaning of the conversation.
3. **Whisper model size is fixed to `tiny`.** This keeps the system lightweight but may reduce transcription accuracy compared with larger Whisper models.
4. **Language/model configuration is not exposed through the program interface.**
5. **No API layer is currently implemented.** The module is currently executed as a local Python pipeline.
6. **No persistent database is used.** Results are stored as JSON.
7. **Input validation and error handling are minimal.**
8. **Keyword lists require manual maintenance.**
